大数.hb

用 HB 自己写的库(仓库 Sample\库\*.hb),通过 包含 "../库/xxx.hb" 编译期内联;一个库一页:正文是库文件开头的说明注释(全文,不截),末尾那张公开方法表是从库源码的 方法 … 声明现场数出来的 —— 库里加一个方法,这一页就多一行。

大数.hb —— 任意精度整数库(纯 HB;不动 ISA、不动关键字、不动语言面)

用法:一份大数 = 一张定长数组 + 两个数(用 = 用了几格,负 = 符号):

包含 "../库/大数.hb";
整数 左[64];  整数 左用 = 0;  整数 左负 = 0;
大数.从文字(左, 左用, 左负, "123456789012345678901234567890");
整数 右[64];  整数 右用 = 0;  整数 右负 = 0;
大数.从整数(右, 右用, 右负, 2);
整数 积[128]; 整数 积用 = 0;  整数 积负 = 0;
大数.乘(积, 积用, 积负, 左, 左用, 左负, 右, 右用, 右负);
输出行(大数.转字符串(积, 积用, 积负));

★ 一份大数长什么样(这一库的内存账):表[] 是低位在前的一串 limb,每格一个 16 位无符号数(0~65535);用 是
"有效的 limb 个数"(用 = 0 就是零);负 是符号。规范形三条:① 用 = 0 ⇒ 一律是零且 负 必须是 0;
② 高位不许留 0 limb;③ 零只有一种写法。
16 位 limb 的理由:一条乘积最大 65535 × 65535 + 65535 + 65535 = 4294967295 = 2³² − 1,**正好装进一个
32 位 无符号整数** ⇒ 乘法一个别的库都不用引(零依赖)。

★ 容量(定长数组 + 有效 limb 个数,不是堆上动态长):表.长度() 就是这一份能装几格,**N 格 = 16N 位 ≈
4.8N 位十进制;常用档 64 格 ≈ 308 位、128 格 ≈ 616 位、256 格 ≈ 1232 位。运算时目标表不够大就给
假(并把目标置零),不静默截断。不做动态长是因为语言里列表取不出地址** ⇒ 状态只能在调用方那张表上。

口径(2026-10;每条都对着实测写):

  • 零依赖:
    一个别的库都不引(长整数 那套不碰);只用 拼接到 这一个内建;
  • 所有函数都不停机:
    容量不够 / 除数得零 / 文本不合法 ⇒ 给 假 或 0,不写错误槽;
  • 除余 的语义照 x86 那一套:
    商 写进你给的 商 表,余数留在被除数 左 里(想留原值先
    拷到 一份);除数为零给 假;
  • 试商用二分:
    每一位商在 0~65535 上二分 16 轮,简单、显然正确,代价是比 Knuth 那套慢约 16 倍;
  • 结果 可以与 左 / 右 是同一张表(加 / 减 / 乘都支持就地;乘 先算进草稿纸再拷回来);
  • 本库不可重入:
    除余 / 转字符串 借的是模块里三张 256 格的草稿纸;
  • 符号规则:
    零一律 负 = 0;谁大 是带符号比较(-1 / 0 / 1);除法是截断除法(商的符号 = 被除数
    符号异或除数符号,余数的符号 = 被除数的符号,且 |余| < |除数|)。

提供的函数(12 个):清零 / 是零 / 从整数 / 从文字 / 转字符串 / 谁大 / 加 / 减 / 乘 / 除余 / 取负 / 拷到;
逐条的参数与返回值见本页末尾那张公开方法表。

英文对照:库里不另立英文函数(中英切换只管关键字与内建函数名,现有几个库也都只有中文名)⇒ 没有英文别名。

复杂度:按"有效 limb 个数 = n" 算 —— 清零 / 从整数 / 是零 / 取负 / 拷到 / 谁大 / 加 / 减 O(n);
从文字 / 转字符串 O(数字位数 × n);乘 O(n²)(教科书竖式);除余 O(16 n²)(每位商二分 16 轮)。

边界(如实登记):

  • 位数由 表.长度() 封顶:
    不是"真任意精度",是"你要多大就开多大";
  • 除余 的余数留在被除数里(x86 语义):
    要留被除数先 拷到;
  • 从文字 只认十进制(不认 0x / 下划线 / 空白):
    不合法给 假 且置零;
  • 不做模幂 / 最大公约数 / 开方 / 素性 / 浮点:
    那些是"用大数写的算法",不是大数本身;
  • 结果 可与 左 / 右 是同一张表;本库不可重入。

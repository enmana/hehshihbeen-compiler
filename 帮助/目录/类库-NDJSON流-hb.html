NDJSON流.hb

用 HB 自己写的库(仓库 Sample\库\*.hb),通过 包含 "../库/xxx.hb" 编译期内联;一个库一页:正文是库文件开头的说明注释(全文,不截),末尾那张公开方法表是从库源码的 方法 … 声明现场数出来的 —— 库里加一个方法,这一页就多一行。

NDJSON流.hb —— 一行一个 JSON 的日志/导出文件,一条一条吃(依赖 JSON.hb)

用法:

包含 "../库/JSON.hb"
包含 "../库/NDJSON流.hb"
如果 (NDJSON流.开读("数据/日志.ndjson"))
{
    当 (NDJSON流.下一条())                 // 坏行自己跳过(条数记在 `坏几条`)
    {
        整数 条 = NDJSON流.当前();          // 这一条解析出来的根节点(交给 JSON.*)
        字符串 级别 = "";
        JSON.取文本(条, "级别", 级别);
        输出行(JSON.取整数(条, "耗时", 0));
    }
    NDJSON流.关读();
}
// 写:一个节点一行
NDJSON流.开写("数据/出.ndjson");
整数 新根 = JSON.新建对象();
JSON.放文本(新根, "级别", "信息");
JSON.放整数(新根, "耗时", 12);
NDJSON流.写一条(新根);
NDJSON流.关写();

几 MB 的日志 / 导出(一行一个 JSON)内存里装不下 —— 一条一条读、读完一条当场解析,常驻只占
一行 + 一份文档的份。解析与取值全归 JSON.hb(这一库只管"一行一行"这一层)。

口径(2026-10;每条都对着实测写):

  • 块级读写:
    库自己开读写流,一次读一块(4096 字节)进一个持久的串变量(反复用同一格),
    逐字节的活走 字符 缓冲(下标 O(1))—— 所以"一条一条吃"不吃字符串池;
  • 坏行跳过:
    不是合法 JSON 的那一行不打断循环(只记个数):坏几条 问得出跳了几条;
    末尾那个空行不算一条;
  • 一条 = 一行:
    行尾的 \r 去掉(Windows 换行也认);末行没有换行也算一条;
  • 节点只在"当前这一条"里有效:
    每读一条都会把 JSON 的"当前那一份"换掉 ⇒ 上一条的节点号当场作废
    (要留什么,读完那一条当场拷进自己的变量);
  • 一次一条流:
    读一条、写一条,各占一个"当前流";要同时开两条就自己交错 关读 / 开读;
  • 失败给假 / 0:
    打不开、没开着、行太长都有确定结果,不报错、不停机。

提供的函数:逐条的作用见本页末尾那张公开方法表。

英文对照:库里不另立英文函数(中英切换只管关键字与内建函数名,现有几个库也都只有中文名)⇒ 没有英文别名。

复杂度:开 / 关 O(1);下一条 O(这一条的字节数 + 解析量);写一条 O(这一条的字节数)。

内存账:静态一个 8KB 的行缓冲 + 一个 4KB 的块缓冲(串变量);一条最长 8000 字节
(含它解析出来的那些节点 —— 上限由 JSON.hb 的节点池与字节区定)。

边界(如实登记,不写"编译器的毛病 + 绕法"):

  • 不做"数组形式的整份 JSON":
    那是 JSON.解析 的活(这一库只认"一行一个");
  • 不做"压缩 / 加密 / 按时间切文件":
    要那些自己在外面套一层(流.hb 的块读写都在);
  • 不做"随机定位 / 跳行":
    只能从头一条条往下走;
  • 写流不建目录(内建就是这口径):
    路径上的目录要自己先建。
